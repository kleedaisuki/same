# same v0.5.1

## 下载 / Downloads

- Windows x64 / Linux x64: `standard` includes CPU + optional OpenCL iGPU; `cuda` additionally includes CUDA.
- macOS Apple Silicon: `standard` includes CPU + optional OpenCL iGPU. There is no CUDA support on macOS.
- CUDA packages require a compatible NVIDIA driver, not a locally installed CUDA compiler. Standard packages need no CUDA runtime.
- Windows packages target Windows 10/11 x64. Linux packages are built on Ubuntu 24.04 (glibc 2.39+). macOS packages target macOS 14+ ARM64.
- Verify `SHA256SUMS` and build provenance before use. Archives include licenses and `build-info.json` with the exact source commit.

## 更新 / Changes

- Reorganized the opt-in human `--summary` report into Results, Storage and I/O, Performance, Compute and routing, Online routing model, Workers, Model persistence, and Telemetry sections.
- Added redundant semantic ANSI highlighting for structure, healthy state, warnings, errors, timings, and routing evidence. Plain output retains all meaning; `NO_COLOR`, per-stream TTY detection, and explicit color policy remain intact.
- Preserved the complete current-run evidence, exact per-worker byte counters, legacy TSV results, raw `key=value` diagnostics, stream contracts, and exit codes.
- Windows launcher now enumerates Visual Studio installations and accepts a CUDA host environment only after the selected `nvcc` compiles and links the same native C++20 probe used by the build. It no longer assumes the newest Visual Studio is compatible.
- `SAME_CUDA_MODE=auto` visibly falls back to CPU only after all candidate host environments fail; strict `on` rejects the build. Explicit caller-owned toolchains remain untouched.

The Windows CUDA package path was locally validated with CUDA 12.8.93 and the Visual Studio 2022 x64 MSVC 19.44 host compiler; all 25 tests passed. Hosted release jobs independently rebuild and test every platform/flavor before publishing their artifacts. Hosted CI does not establish physical GPU performance.
