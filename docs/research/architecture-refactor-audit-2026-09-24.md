This is a source audit, not a benchmark or test run. The current uncommitted traversal/security work was excluded. Preserve CLI text, output ordering, state schema, library overloads, and failure semantics. Prefer the first two small changes below; the third is conditional on measured maintenance need.

## Invariants and representative transition

The normal flow should become `ParallelWalk::Entry -> HashCandidate -> hash_file -> FileRecord -> Store::save`. A candidate owns the unread handle and has no digest field; a stored record has a digest computed from the bytes of its checked `FileStamp`. A `ComputeError` retry must still consume the first handle once, then reopen from offset zero, and must not emit or save a partially hashed record. Existing `FileRecord` remains intentionally public for Store users, so this refinement prevents an application-path mistake rather than making every possible external misuse unrepresentable. The [C++ Core Guidelines I.4/C.2](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) support precise interfaces and explicit invariants; academic [typestate work](https://research.ibm.com/publications/typestate-a-programming-language-concept-for-enhancing-software-reliability) is the broader idea, **not** evidence that a full typestate library would pay for itself here.

For routing, the state is policy + worker-owned selected device, not three independent policy flags. Convert the validated string once inside `Resources`; leave `Config` serialization as-is. Construction must still allocate the same CPU/GPU budgets, initialize devices lazily, and preserve forced CUDA/iGPU fallback behavior. Invalid strings must retain the current validation error path; parsing must not silently default to CPU.

## Rejected broader changes

Do not turn `Store::begin_scan/end_scan` into a new public typestate API: its destructor already rolls back unfinished scans, and an additional adapter would add indirection while risking library compatibility. Do not split the 1,700-line `application.cpp` merely by line count; cohesive splits should follow proven ownership boundaries (hash candidate or report snapshot) and executable regression tests. Do not add a strategy hierarchy for four backend policies; one enum is sufficient. The [SQLite transaction contract](https://sqlite.org/lang_transaction.html) supports the existing explicit commit/rollback boundary; none of these recommendations changes it.
