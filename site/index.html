构建与安装

需要 CMake 3.25+ 和 C++23 编译器。CUDA 可选；没有 GPU 也能工作。Windows 请在 VS x64 开发者终端构建。进入需要检查的目录后运行程序。

git clone https://github.com/kleedaisuki/same.git
cd same
cmake --preset release
cmake --build --preset release

日常命令

same new
生成完整默认配置和推荐 ignore，不覆盖已有文件。
same scan -r
递归扫描；省略 -r 只扫描当前目录。
same --summary
显示统一 Summary 表，含结果、数据库及性能统计。
same clean [-r]
删除 .same 状态；-r 扩展到子目录。包含配置、ignore 和遥测历史，请先备份。

统一线程设计 ↗
遥测开销与验证 ↗

  • 固定数量的工作线程共享任务队列，各自学习真实任务成本并选择 CPU SIMD 或自己的 CUDA 执行流；首次设备初始化时其他线程继续用 CPU，就绪后多流并发；启动不运行合成性能校准。
  • 默认小于 16 MiB 直接走 CPU；这是 GPU 资格下界，不是保证提速的交叉点。合格任务按线程本地模型选择，多流共享设备；可恢复的设备错误由该线程完整回退 CPU。
  • 新增跨运行的 .same/telemetry.db：异步批量保存日志、追踪、指标及完整模型参数。--summary 仍仅显示本次运行；遥测损失和退出等待可见。
  • --no-pgo 关闭在线学习与哈希采样，--no-telemetry 关闭遥测入库，两者独立。未知配置字段直接忽略。
  • 用外部 SQLite 客户端检索；独立 Python 脚本 ↗ 可合并多份遥测库为归档，不把查询服务放进扫描程序。
缓存依赖文件元数据，并非文件系统快照。需要完整重算时使用 --rehash；可靠审计请扫描静止目录。性能随硬件、文件分布与磁盘缓存变化；GPU 初始化仍可能拖慢短批次。异步遥测仍占用资源，退出时需等待写入，不承诺零开销。
